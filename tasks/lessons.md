# 教訓

## 実装・API 調査

### 「取れたデータ」と「求められたデータ」を混同しない

**事象**: 移籍データの可視化を依頼され、`division-ranking/*/transfersExperts|transfersLosers` を主データに据えて実装した。しかしこれは「儲かった/損した移籍の上位数件」というランキングの抜粋であり、ユーザーが求めていた「どの選手がどのフェーズでいくらで落札されたか」という**全取引の記録ではなかった**。完成後に指摘を受けて全面的に作り直した。

**原因**: 最初に 200 が返ったエンドポイントで満足し、それが要件を満たすか検証しなかった。「移籍」という語が付くエンドポイントを見つけた時点で探索を打ち切っている。

**再発防止**:
- API 探索では「動いた」で止めず、**返ってきたデータが要件の粒度・母集団と一致するか**を確認する。件数が不自然に少ない（18件しかない等）のは母集団が違う兆候である。
- ランキング系（`*-ranking`）は集計結果であり、生データは別にあると疑う。履歴・ログ系（`*-history`）を先に探す。

### 一括取得の経路だけを見て「不可能」と結論しない

**事象**: 選手名の解決で、プール API（`championship-players-pool`）が現行シーズン分しか返さないことを確認し、「過去の選手の名前は解決不能」とユーザーに報告した。実際には `/championship-player/{playerId}` で個別に取得でき、全件解決できた。

**原因**: 「名前は一括で引くもの」という思い込みで、個別取得の経路を試していなかった。

**再発防止**: 「できない」と報告する前に、一括取得・個別取得・履歴経由の3方向を試す。不可能の断定は、可能性を潰し切ってから行う。

### 推測で決め打ちせず、実リクエストを捕獲する

**事象**: フロントバンドルの解析だけでエンドポイントとヘッダを組み立てたところ、必須ヘッダ（`application` / `client-version`）が欠けて全リクエストが 400 になった。ユーザーがブラウザから実リクエストを提供してくれて解決した。

**再発防止**: SPA の内部 API を利用する際は、バンドル解析を出発点としつつ、**実際に飛んでいるリクエストのヘッダ一式を最初に確認する**。認証ヘッダだけでは足りないことが多い。

## データ分析・入札額の判断

### 1件のデータの「文脈」を確かめずに集計しない（最重要）

**事象**: 入札額の妥当性を過去の落札データから助言する際、2度続けて誤った基準を提示し、いずれもユーザーの指摘で訂正した。

1. **全シーズンを平等に集計した** → 相場は年々下落しており（S3 +14 → S8 +4）、古い高騰期に引きずられて過大な推奨（+11）を出した
2. **競合の有無を見ずに落札額を集計した** → GK の 81% は単独入札で、その上乗せ中央値は +1。競合なしの高額落札は「相場」ではなく**落札者の過払いの記録**であり、それを根拠に推奨額を積み上げていた

**原因**: 件数の多さ（95件、167件）に安心し、1件1件が「どういう状況で成立した価格か」を確かめなかった。集計は母集団を均質と仮定するが、実際には**性質の異なるデータが混在**していた。

**再発防止**:
- 時系列データは**まず年次推移を見る**。全期間の平均・中央値を出すのは推移が横ばいと確認してから
- 価格データは**成立条件（競合の有無・入札者数）で層別してから**集計する。「いくらで売れたか」と「いくら必要だったか」は別物
- 極端な値を見つけたら、それを基準にする前に**なぜその値になったかを1件ずつ確認**する

### ユーザーの指摘は仮説ではなく検証対象として扱う

**事象**: 「GK は枠が1つで代替が効かないので、売れ残っていても安全とは言えない」との指摘を受け、チーム別の獲得数を調べたところ、全10チームが漏れなく GK を確保し大半が2名で止めていた。「22名売れた＝品薄でない」という拙者の読みは誤りだった。

**原因**: 落札総数だけを見て、それが「余っている」のか「全チームが必要数を満たして市場が閉じた」のかを区別しなかった。

**再発防止**: 総数ではなく**分布（誰が何個持っているか）**を見る。ドメイン知識に基づく指摘を受けたら、同意も反論もせず**まずデータで検証する**。

### 分析の前提が変わったら、過去の結論を明示的に訂正する

**事象**: 判断軸が変わるたびに推奨額が 65〜73 → 55〜61 → 60〜65 → 49〜52 と大きく動いた。

**再発防止**: 前提が覆ったときは、新しい結論を述べるだけでなく**どの前提が誤っていたかを明示**して訂正する。数字だけ差し替えると、相手はどちらを信じてよいか判断できない。
